# Install ios-release

[Documentation](README.md) · [Quickstart](native-quickstart.md)

## Published native binary

The current native package is
[0.2.0-beta.1](https://github.com/northcutted/ios-release-workflows/releases/tag/native-v0.2.0-beta.1),
published from `a3c32bcae61a8a174f3c5ea6a4ba0b623aaaf33a`.
Install [GitHub CLI](https://cli.github.com/) and authenticate with `gh auth login`.
No repository clone or Rust toolchain is needed.

```sh
task_installer="$(mktemp)"
curl -fsSL https://raw.githubusercontent.com/northcutted/ios-release-workflows/a3c32bcae61a8a174f3c5ea6a4ba0b623aaaf33a/scripts/install-native.sh -o "$task_installer"
bash "$task_installer" 0.2.0-beta.1 "$HOME/.local" a3c32bcae61a8a174f3c5ea6a4ba0b623aaaf33a
rm "$task_installer"
export PATH="$HOME/.local/bin:$PATH"
ios-release doctor
```

Add the PATH line to your shell configuration to keep it across terminal sessions.
The installer downloads the platform-specific binary and `SHA256SUMS`, checks the
checksum, and verifies GitHub provenance against the official packaging workflow,
source commit, main branch, and hosted runner. Verification completes before the
binary is installed or executed.

| Platform | Native package | What runs there |
| --- | --- | --- |
| macOS Apple silicon | `ios-release-macos-arm64` | Full CLI with Xcode installed |
| macOS Intel | `ios-release-macos-x86_64` | Full CLI with Xcode installed |
| Linux x86_64 | `ios-release-linux-x86_64` | Apple API and release-management commands; no Xcode builds |

The native executable needs no language runtime. Builds/tests need the configured
Xcode, SDK, and simulator runtime; signing uses OpenSSL and Keychain tools.
SwiftLint is needed only when lint is configured. See [supported scope](native-status.md).

## Existing installations and upgrades

The installer refuses to overwrite an existing `PREFIX/bin/ios-release`.
For a rehearsal or upgrade, use a new prefix, for example
`"$HOME/.local/share/ios-release/0.2.0-beta.1"` as its second argument. Invoke the
new binary by its full path until you have reviewed its behavior and workflow pin.
Your old installation remains available for rollback and older releases.

The published beta's `doctor` and `--version` report the Cargo version `0.2.0`;
the package version is `0.2.0-beta.1`. Check `doctor.platform_revision` against the
commit above to identify that package's source. Subsequent builds expose the
distribution version directly when packaging supplies it.

Workflows generated by a published binary install that same verified package and
require its source to match their immutable platform pin. Development binaries
generate workflows that compile the pinned source. Changing a version string
alone is insufficient: package and source pin must agree.

Manage an older delivered release using its original CLI version and producer pin
until producer migration is validated. Preserve release files before the Actions
[90-day retention window](native-releases.md#preserve-and-recover-a-release) expires.

## Build from source

For development, clone this repository and check out the full revision you intend
to review. Install [Rust](https://rustup.rs/), then build using the checked-in
toolchain and lockfile:

```sh
git clone https://github.com/northcutted/ios-release-workflows.git
cd ios-release-workflows
make native-build
./rust/target/release/ios-release doctor
```

Invoke that binary explicitly when testing another app. `doctor.platform_revision`
records the build's source commit; uncommitted edits are development work and do
not constitute a reviewed release. Do not substitute a development binary for a
published preparation's original producer.
